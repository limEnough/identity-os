# Identity OS

> **문득 궁금해요, 나는 어떤 사람일까요?**
>
> 나를 이루는 요소들에 이름 붙여가며 나를 가다듬는 여정에 함께해요. 정답도, 점수도, 판정도 없어요 — 여정의 끝에 남는 것은 **나의 문장**입니다.

---

## 여정

```
인트로 ──▶ Why 체인 (7걸음) ─────▶ My Life Guide ──▶ 무드 체인 (7걸음) ──▶ 가이드북
 오브,       동경 → 부러움의 정체 →     나의 문장 (손글씨)   장면 → 질감 → 빛 →      + 나의 무드
 시작 전      순간 → 이유 → 근원 →      이번 주의 실천       색 → 거리 → 명명 → 표현  (색·좌표·표현 언어)
 confirm     명명 → 실천              8섹션 가이드북       (가치 위에서 감각을 묻는다) 이번 주의 표현
             (깊은 질문엔 "넘어갈래요")   ↑ Style 섹션 해금 ────┘
```

- **인트로** — 오브가 묻는다: "나는 어떤 사람인가요?" 시작 버튼을 누르면 confirm이 뜬다: _"모두가 이용 가능한 대신, 입력한 정보를 저장하지 않아요. 대신 이렇게 당신을 알아볼게요. 확인 버튼을 클릭하면 창을 닫았다가 나중에 다시 와도 걷던 그 길 그대로 다시 걸어볼 수 있어요."_ — 계정 없음, 서버 저장 없음, 발자국은 이 브라우저에만.
- **Why 체인 (Identity)** — 부러움을 거울 삼아 내 가치를 찾는 7걸음. **넓게 물어 좁게 닫는다**: 동경 유형(6) → 부러움 포인트(유형마다 4) → 그 마음이 찾아오는 순간(유형마다 4+넘어감) → 이유(6+넘어감) → 근원(6+넘어감) → 명명(오브의 '제안' 하나 + 결이 다른 대안 둘 + 유보, 가치 후보 59종) → 실천(4~5). 고른 '순간'과 동경은 실천 카드에 그대로 실린다 — 일반론이 아니라 그 사람의 하루에 붙은 행동이 되도록.
- **My Life Guide** — 손글씨로 쓰인 나의 문장, 이번 주의 실천 하나, 그리고 8섹션 가이드북. Identity가 정의된 순간 **Style 섹션이 열리고, 눌러서 걸어 들어갈 수 있다.**
- **무드 체인 (Style)** — Identity가 "왜?"를 파고든다면 Style은 **감각을 묻는다**. 장면(6) → 질감(장면마다 4) → 빛(5+넘어감) → 색(6+넘어감) → 거리(5+넘어감) → 명명(제안 + 다른 결 + 이웃 무드 + 유보) → 표현(4~5). 선택마다 세 축(고요함↔생동감 · 부드러움↔또렷함 · 오래된 것↔지금의 것)에 좌표가 쌓이고, 그 좌표가 **무드 8종** 중 하나로 수렴한다. 명명 화면에서는 오브가 무슨 근거로 그렇게 말했는지 축 막대를 함께 보여준다 — 판정이 아니라 거울이므로.
- **뿌리에서 자라는 잎** — 무드 체인은 **Identity에서 확정된 가치 위에서** 걷는다. 가치는 좌표의 출발점을 기울이고(`VALUE_LEAN`, 가치 59종 → 일곱 갈래의 기울기), 질문의 말끝과 코치의 발화와 표현 카드의 마지막 장에 그대로 실린다. 기울기의 크기는 한 걸음의 절반 아래 — **판정이 아니라 출발점이라, 다섯 번의 감각 선택이 언제든 되돌릴 수 있다.** 그래서 `replayStyle(발자국, 가치)`는 가치를 함께 받는다: 같은 발자국도 뿌리가 다르면 다른 무드에 닿는다.
- **경계에서 좁히기** — 8분면은 경계에서 갈리고, 0.49와 0.51은 거의 같은 사람이다. 그래서 명명 화면은 제안 하나로 닫지 않고 **가장 아슬아슬했던 축을 뒤집은 이웃 무드**를 함께 내민다("조금 다른 쪽이에요 — 「차분한 미니멀」"). 그걸 고르면 이름만이 아니라 무드 자체가 경계 너머로 옮겨간다. 확정된 이름 옆에는 **가장 크게 기운 축**이 한 줄 붙는다 — "「선명한 생동」 — … · 지금의 것 쪽으로".
- **나의 무드** — 이름·세 축 좌표, 그리고 무드를 네 갈래(옷차림·공간·말과 태도·곁에 두는 것)의 표현 언어로 펼친 카드. 무드가 정해지면 나의 문장에 _"그래서 「…」의 무드에 끌렸는지도 모른다"_ 한 줄이 얹힌다.

### 제품 불변식

1. **Identity → Style. 절대 역방향 금지.** 가이드북의 Style 섹션은 나의 문장이 생긴 뒤에야 열린다. 문서가 아니라 **라우트에서 강제된다** — `/style`은 Identity를 완주하지 않은 발자국으로는 열리지 않고 인트로로 되돌린다.
2. **분석하는 것은 롤모델이 아니라 사용자다.** 부러움은 언제나 사용자 내면을 비추는 거울로만 쓴다.
3. **코치는 답하지 않는다. 묻는다.** 오브의 발화는 질문·반영·명명 제안으로 제한된다. "당신은 ~형입니다" 같은 판정 금지.
4. **모든 깊은 질문에는 "넘어갈래요"가 있다.** 자기 탐색은 자발적일 때만 유효하다.

### ver1 / ver2

- **ver1 (현재)**: 구조화된 결정론적 트리만으로 동작. LLM 없음, 서버 코드 없음, 회원 DB 없음 — **완전 정적 배포 가능**. 환경 변수도 외부 API도 없다.

## 상태 모델 — 축마다 발자국 하나

원본 상태는 **응답 시퀀스(발자국)** 뿐이다. 분기가 전부 결정론적 순수 함수라서, `2.0.9.1.0.2` 같은 짧은 문자열만 있으면 여정의 어느 지점이든 리플레이로 복원된다. 무드 좌표조차 저장하지 않는다 — 발자국에서 매번 다시 계산된다.

- 축마다 발자국 하나: Identity는 `i`, Style은 `s`. 걸음마다 **URL**(`/identity?i=…`, `/style?i=…&s=…` — 새로고침·공유)과 **브라우저 기억**(재방문 시 "이어서 걷기" 배너)에 이중 기록한다.
- `/guide?i=…&s=…` URL 복사만으로 결과 공유가 성립한다. `s`가 없으면 가이드북은 Style 섹션이 열린 채로, 아직 걷지 않은 상태로 그려진다.
- 두 발자국은 **따로 기억되지만 따로 읽히지는 않는다** — Style은 Identity 위에 얹힌 잎이므로, 무드 발자국은 확정된 가치와 함께여야 되짚힌다(`replayStyle(s, 가치)`). 그래서 `s`는 언제나 `i`를 데리고 다니고, Identity를 처음부터 다시 걸으면 무드도 함께 지워진다.
- 넘어간 질문은 `9`로 기록된다 — 건너뜀도 존중되는 데이터다. 무드 축에서 넘어간 걸음은 좌표를 움직이지 않는다(중앙에 남는다).

## 디자인 — 빛으로 숨 쉬는 미니멀

오로라가 번지는 아이스 블루 배경, 4초 주기로 숨 쉬는 **오브 코치**(발광하는 눈, 회고를 기다릴 땐 잠드는), 소프트 글로우 카드, 플로팅 CTA(콘텐츠만 스크롤). 서체는 UI 전부 Pretendard 하나, **'나의 문장' 한 곳만 나눔손글씨 '강인한 위로'** — 시스템이 출력한 결과가 아니라 내가 눌러쓴 다짐처럼.

스타일은 전부 **Tailwind CSS v4** 유틸리티로 적는다. 색·서체·굴곡·그림자·움직임은 `design-system/src/styles.css`의 `@theme` 토큰 하나로 모이고(`bg-card`·`text-sub`·`shadow-card`·`animate-breathe`), 되풀이되는 조합은 `recipes.ts`에 관용구로 이름을 얻는다(`surface`·`surfaceLift`·`accentFill`). CSS 파일에 남는 것은 셋뿐 — 토큰, 유틸리티로 쓸 수 없는 것(`scrollbar-gutter`·`overflow-x:clip`·조상 선택자가 필요한 `serif-ready` 변이), 그리고 한 덩어리로만 뜻을 갖는 그림(오브의 4겹 그라데이션).

## 프로젝트 구조

npm workspaces 모노레포. 지금은 하나로 배포되지만, 경계는 처음부터 마이크로 프론트엔드입니다.

```
identity-os/
├─ apps/web/                    # Next.js 앱 셸 — 라우팅·저장소 주입·불변식 게이트 (서버 코드 없음, 완전 정적)
│  ├─ app/page.tsx              #   인트로 (오브 + 시작 전 confirm)
│  ├─ app/identity/             #   Why 체인 (7걸음)
│  ├─ app/style/                #   무드 체인 (7걸음) — Identity 미완주면 인트로로 되돌린다
│  ├─ app/guide/                #   My Life Guide — page + GuideSections(8섹션 목차) + GuideNotes(쪽지)
│  ├─ app/_lib/                 #   셸의 공통 배선 — 저장소(progress)·라우트(useChainRoute)·불변식 게이트
│  └─ app/_components/          #   셸 전용 조각 (이어걷기 배너)
├─ packages/
│  ├─ identity-core/            # 도메인 두뇌 — 두 축의 트리·리플레이 엔진·무드 좌표계·문장 빌더·조사 헬퍼·저장 어댑터 (순수 TS)
│  ├─ design-system/            # 토큰(styles.css)·관용구(recipes.ts)·컴포넌트
│  │  ├─ layout/ primitives/    #   앱 골격(오로라·화면·플로팅 CTA) · 낱개(버튼·칩·팝업·글)
│  │  ├─ orb/ icons/ fonts/     #   오브와 말풍선 · 인라인 SVG 아이콘 · 손글씨 서체 문지기
│  │  └─ chain/                 #   여정의 공통 골격 — 두 체인이 함께 쓰는 화면·걸음 점·선택지·축 막대·상태 훅
│  ├─ feature-identity/         # Why 체인 — 어떤 트리를 걷는지만 정한다 (화면은 chain/)
│  └─ feature-style/            # 무드 체인 + 무드 카드 (축 막대·표현 언어)
└─ docs/identity-os-design.md   # 제품 설계 (8축 프레임워크·AI 코치·로드맵)
```

MFE 경계 규칙: 피처는 라우팅·저장 방식을 모르고 전부 앱 셸이 props로 주입한다. `identity-core`는 React조차 모르는 순수 TS — 테스트가 집중되는 곳.

두 체인의 화면은 `design-system/chain/`에 하나로 모여 있다. Identity와 Style은 같은 골격(걸음 점 → 물음 또는 코치의 제안 → 선택지 → 넘어가기 → 발견 조각)을 걷고, 축마다 다른 것은 **어떤 트리를 리플레이하는지**와 명명 화면에 근거(축 막대)를 함께 두는지뿐이다. 그래서 `chain/`은 도메인을 모른다 — 걸음의 겉모습(`ChainStepView`)과 리플레이 함수만 받는다.

## 지켜야 할 것

- Why 체인의 "왜"는 최대 5회 — 심문이 되지 않게. 모든 깊은 질문에 넘어가기.
- 성장 압박 속에 어떤 기능이 들어와도, Style 섹션의 잠금 순서(Identity 먼저)는 불변식이다.
