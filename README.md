# Identity OS

> **문득 궁금해요, 나는 어떤 사람일까요?**
>
> 나를 이루는 요소들에 이름 붙여가며 나를 가다듬는 여정에 함께해요. 정답도, 점수도, 판정도 없어요 — 여정의 끝에 남는 것은 **나의 문장**입니다.

---

## 여정

```
인트로 ──▶ 1 Identity ──▶ 2 Mindset ──▶ 3 Communication ──▶ 4 Lifestyle ──┐
 오브,        가치            생각의 결        관계의 결            하루의 결      │
 시작 전   ┌──────── 축을 끝내면 가이드북으로 돌아오고, 거기서 다음 축 하나가 열린다 ──┤
 confirm   └──▶ 5 Taste ──▶ 6 Style ──▶ 7 Health ──▶ 8 Career ──▶ 여덟 축의 가이드북
                끌림의 결      무드         돌봄의 결      성장의 결      + 나의 문장(손글씨)
                                                                        + 나의 네 글자(봉인)
```

돌아올 때마다 가이드북에서 세 가지가 자란다: **나의 네 글자**(축마다 한 자리씩 또렷해진다) · **결 서재**(하루 한 꾸러미) · **결 연표**(판마다 날짜가 붙는다).

여덟 축은 모두 **같은 일곱 걸음**을 걷는다. 넓게 물어 좁게 닫는다:

```
0 입구(6갈래) → 1 그 안의 구체(입구마다 4) → 2·3·4 깊은 물음 셋(5~6 + "넘어갈래요")
→ 5 명명(제안 + 같은 결의 다른 이름 + 경계 너머의 이웃 + 유보) → 6 이번 주의 한 가지(4~6)
```

- **인트로** — 오브가 묻는다: "나는 어떤 사람인가요?" 시작 버튼을 누르면 confirm이 뜬다: _"모두가 이용 가능한 대신, 입력한 정보를 저장하지 않아요. 대신 이렇게 당신을 알아볼게요."_ — 계정 없음, 서버 저장 없음, 발자국은 이 브라우저에만.
- **순서가 곧 의존이다** — 축 N은 그 앞의 축들이 모두 완주됐을 때만 열린다. 건너뛰기는 없다. 그리고 **다시 걸을 수 있는 것은 바로 앞의 축 하나**(= 가장 마지막에 확정한 축)뿐이다. 그보다 앞으로 되돌아가면 그 위에 얹힌 축들이 근거를 잃기 때문이다 — 다시 걸으면 그 축부터 뒤가 함께 지워진다.
- **뒤 축은 앞 축 위에서 걷는다** — 축을 하나 지날 때마다 그 결과가 **누적 프로필**(네 갈래의 결: 고요함↔생동감 · 부드러움↔또렷함 · 오래된 것↔지금의 것 · 안으로↔밖으로)에 각인되고, 다음 축은 자기 세 극으로 그 결을 투영해 **좌표의 출발점을 기울인 채** 시작한다. 크기는 걸어온 축이 많을수록 커지지만 한 걸음을 넘지 않는다 — **판정이 아니라 출발점이라, 그 축의 다섯 선택이 언제든 되돌린다.**
- **인용도 함께 쌓인다** — 앞 축의 확정된 이름은 물음의 말끝("「단단함」이 가장 크게 시험되는 순간은?"), 코치의 명명 발화("가치 「단단함」을 아는 사람의 결이라면…"), 발견 조각의 첫 자리, 그리고 실천 카드에 그대로 실린다. 그래서 **8번 축에 닿은 사람은 일곱 축의 결을 데리고 오고**, 같은 8분면 안에서도 더 세밀한 변주를 받는다.
- **명명 — 경계에서 좁히기** — 좌표는 8분면으로 갈리고, 0.49와 0.51은 거의 같은 사람이다. 그래서 명명 화면은 제안 하나로 닫지 않고 **가장 아슬아슬했던 극을 뒤집은 이웃 결과**를 함께 내민다("조금 다른 쪽이에요 — 「열린 실험」"). 확정된 이름 옆에는 **가장 크게 기운 극**이 한 줄 붙는다. Identity만은 예외로, 이름이 좌표가 아니라 고른 갈래에서 온다(가치 후보 59종이 이미 8분면보다 세밀하므로).
- **My Life Guide** — 축을 끝낼 때마다 돌아오는 자리. 걸어온 축은 채워진 채로, **다음 축 하나만 '방금 열림'으로**, 그 뒤는 잠긴 채로 놓인다. 축마다 쪽지 하나(이름·쉬운 한 줄·세 극 좌표·잘 통하는 자리와 힘든 자리·네 갈래의 표현 언어·이번 주의 한 가지)가 쌓이고, 맨 앞에는 손글씨로 쓰인 **나의 문장**이 있다 — 축을 하나 지날 때마다 절이 하나 붙어 함께 자라는 글.

## 나의 네 글자 — 걸어야 채워지는 표식

축 하나의 이름이 **8분면(세 극)** 에서 온다면, 네 글자는 **여정 전체(네 갈래)** 에서 온다. 새로 만든 좌표가 아니라 이미 있던 `Canon`을 꺼내 보이는 것이다.

| 갈래      | −         | +         | 글자    |
| --------- | --------- | --------- | ------- |
| `vivid`   | 고요함    | 생동감    | **Q/V** |
| `sharp`   | 부드러움  | 또렷함    | **S/K** |
| `modern`  | 오래된 것 | 지금의 것 | **R/N** |
| `outward` | 안으로    | 밖으로    | **I/O** |

→ `QSRI` 「오래된 서재」, `VKNO` 「광장의 신호등」 … **열여섯 자리.** 이름은 전부 장소다 — 사람을 유형으로 부르면 판정이 되지만, 자리로 부르면 "지금 잘 지내는 곳"이 된다.

```
축 1 완료   · · · ·        축 4 완료   Q S · ·
축 6 완료   Q S · I        축 8 완료   Q S R I  「오래된 서재」  ← 봉인
```

- **끝에 주지 않고 처음부터 흐릿하게 준다.** 한 축으로 자리를 잡는 글자는 평균 반 자리이고, 네 자리가 다 차려면 대개 여섯 축이 넘게 걸린다. 축을 끝낼 때마다 눈에 보이는 것이 늘어난다 — 그리고 정직하다: 실제로 덜 확실하므로 덜 확실하게 보인다.
- **한가운데가 이 계산의 전부다.** 각인은 네 갈래 모두 양(+)으로 치우쳐 있고 앞 축이 뒤 축을 같은 방향으로 기울이므로, 0을 기준으로 부호만 읽으면 열여섯 중 하나가 절반을 먹는다. 그래서 기준을 **걸어서 닿는 값들의 한가운데**(`CENTER`)로 옮긴다. 표를 평균한 값이 아니라 측정값이라, 축 데이터를 손보면 어긋난다 — 관문은 `code.test.ts`의 분포 테스트.
- **결 서재** — 하루에 한 꾸러미: 「한 구절, 그리고 그것이 온 책」 + 노래 하나. 추천이 아니라 선물이라 링크를 두지 않고 **제목만 복사**한다. 가사는 싣지 않는다.
- **결 연표** — 여덟 축을 다 걸면 그 판이 날짜와 함께 봉인된다. 계절(90일)이 지나면 **한 판을 새로 걷기**를 권한다(중간 축 재걷기가 아니다 — 순서 불변식은 그대로). 지난 판은 지워지지 않으므로 `QSRI → QSNI` 같은 이동이 그대로 남는다.
- **겹쳐보기**(`/together`) · **열여섯의 지도**(`/codes`) — 점수도 궁합도 없다. 갈린 갈래에는 서로에게 물어볼 질문 하나가 놓인다. 링크에 실리는 것은 네 글자뿐이다.

### 제품 불변식

1. **1 → 8. 순서를 어기는 길은 없다.** 앞 축이 완주되지 않으면 뒤 축은 열리지 않고, 다시 걸을 수 있는 것은 마지막에 확정한 축 하나뿐이다. 문서가 아니라 **라우트에서 강제된다**(`walkJourney`의 계산을 그대로 쓰는 `/[축]` 가드).
2. **분석하는 것은 롤모델이 아니라 사용자다.** 부러움은 언제나 사용자 내면을 비추는 거울로만 쓴다.
3. **코치는 답하지 않는다. 묻는다.** 오브의 발화는 질문·반영·명명 제안으로 제한된다. "당신은 ~형입니다" 같은 판정 금지.
4. **모든 깊은 질문에는 "넘어갈래요"가 있다.** 자기 탐색은 자발적일 때만 유효하다. 넘어간 걸음은 좌표를 움직이지 않는다(중앙에 남는다).
5. **뿌리는 출발점이지 판정이 아니다.** 앞 축의 기울기는 한 걸음보다 작다 — 그 축에서 고르는 다섯 걸음이 언제든 뒤집을 수 있어야 한다.
6. **네 글자는 성격유형이 아니다.** 넷을 모두 지킬 때만 존재한다 — (a) 문항 채점이 아니라 **걸어야** 채워지고, (b) **날짜가 붙어** 계절마다 다시 쓰이고, (c) 가이드북 **안에** 놓여 어느 갈래에서 왔는지 펼쳐지고, (d) **궁합·점수·순위를 만들지 않는다.** 겹쳐보기가 등급 대신 질문을 내미는 것은 취향이 아니라 방어선이다.

### ver1 / ver2

- **ver1 (현재)**: 여덟 축 전부가 구조화된 결정론적 트리만으로 동작. LLM 없음, 서버 코드 없음, 회원 DB 없음 — **완전 정적 배포 가능**. 환경 변수도 외부 API도 없다. 네 글자·서재·연표·겹쳐보기까지 전부 정적이다(서버가 필요한 것은 OG 공유 카드 하나뿐이고, 그건 아직 하지 않았다).
- **ver2 (설계됨)**: LLM 코치 심화 모드(자유 대화 → Insight 추출, 위기 신호 안전장치), 실천·회고 루프(계정+Supabase), 축 콘텐츠 심화. 설계는 [`docs/identity-os-design.md`](docs/identity-os-design.md).

## 상태 모델 — 걷는 것과 간직되는 것

원본 상태는 **응답 시퀀스(발자국)** 뿐이다. 분기가 전부 결정론적 순수 함수라서, `2.0.9.1.0.2.0` 같은 짧은 문자열만 있으면 여정의 어느 지점이든 리플레이로 복원된다. 좌표도 결과도 저장하지 않는다 — 발자국과 프로필에서 매번 다시 계산된다.

- 축마다 발자국 하나, 파라미터 한 글자: `i`(Identity) `m`(Mindset) `c`(Communication) `l`(Lifestyle) `t`(Taste) `s`(Style) `h`(Health) `k`(Career). 걸음마다 **URL**(새로고침·공유)과 **브라우저 기억**(재방문 시 "이어서 걷기" 배너)에 이중 기록한다.
- 주소는 언제나 **걸어온 축 전부**를 싣고 다닌다(`/style?i=…&m=…&c=…&l=…&t=…`). 뒤 축은 앞 축의 결과 없이는 되짚을 수 없으므로 — `replayAxis(축, 발자국, 프로필)`.
- `/guide?i=…&m=…` URL 복사만으로 결과 공유가 성립한다. 주소에 없는 축이 이 브라우저의 기억에 남아 있으면 가이드북이 되살려 주소에 다시 싣는다.
- 순서를 어긴 발자국은 **읽지 않는다** — 앞 축이 끝나지 않았으면 뒤 축의 기억은 기억이 아니라 오류이므로. 어긋난 발자국은 어긋나기 직전까지만 살린다.
- 넘어간 질문은 `9`로 기록된다 — 건너뜀도 존중되는 데이터다.

그리고 **수명이 다른 것 둘**이 있다. 발자국은 '지금 걷는 판'의 것이라 다시 걸으면 지워지지만, **서재와 연표는 판이 바뀌어도 남는다** — 지난 계절의 네 글자와 그때 꽂아둔 구절이 지워지면 "나는 계속 수정된다"를 보여줄 수가 없으므로. 둘 다 이 브라우저에만 있고, 저장 방식을 아는 것은 여전히 앱 셸뿐이다(`_lib/keepsake.ts`).

## 디자인 — 빛으로 숨 쉬는 미니멀

오로라가 번지는 아이스 블루 배경, 4초 주기로 숨 쉬는 **오브 코치**(발광하는 눈, 회고를 기다릴 땐 잠드는), 소프트 글로우 카드, 플로팅 CTA(콘텐츠만 스크롤). 서체는 UI 전부 Pretendard 하나, **'나의 문장' 한 곳만 나눔손글씨 '강인한 위로'** — 시스템이 출력한 결과가 아니라 내가 눌러쓴 다짐처럼.

스타일은 전부 **Tailwind CSS v4** 유틸리티로 적는다. 색·서체·굴곡·그림자·움직임은 `design-system/src/styles.css`의 `@theme` 토큰 하나로 모이고(`bg-card`·`text-sub`·`shadow-card`·`animate-breathe`), 되풀이되는 조합은 `recipes.ts`에 관용구로 이름을 얻는다(`surface`·`surfaceLift`·`accentFill`). CSS 파일에 남는 것은 셋뿐 — 토큰, 유틸리티로 쓸 수 없는 것(`scrollbar-gutter`·`overflow-x:clip`·조상 선택자가 필요한 `serif-ready` 변이), 그리고 한 덩어리로만 뜻을 갖는 그림(오브의 4겹 그라데이션).

## 프로젝트 구조

npm workspaces 모노레포. 지금은 하나로 배포되지만, 경계는 처음부터 마이크로 프론트엔드입니다.

```
identity-os/
├─ apps/web/                    # Next.js 앱 셸 — 라우팅·저장소 주입·순서 게이트 (서버 코드 없음, 완전 정적)
│  ├─ app/page.tsx              #   인트로 (오브 + 시작 전 confirm)
│  ├─ app/identity/ … career/   #   여덟 축의 라우트 — 축 id만 넘기는 다섯 줄짜리 파일 여덟 개
│  ├─ app/guide/                #   My Life Guide — page + GuideSections(8섹션 목차) + GuideNotes(쪽지)
│  │  └─ GuideKeepsakes.tsx     #     간직되는 것들 — 네 글자 쪽지·결 서재·결 연표
│  ├─ app/codes/                #   열여섯의 지도 — 내 칸과 옆칸
│  ├─ app/together/             #   겹쳐보기 — 점수 없이 질문 하나
│  ├─ app/_lib/                 #   셸의 공통 배선 — 발자국(progress)·간직되는 것(keepsake)·순서 게이트(AxisRoute)
│  └─ app/_components/          #   셸 전용 조각 (이어걷기 배너)
├─ packages/
│  ├─ identity-core/            # 도메인 두뇌 (순수 TS)
│  │  ├─ axis/canon.ts          #   축을 가로지르는 결 벡터 — 앞 축의 각인이 뒤 축으로 투영되는 통로
│  │  ├─ axis/code.ts           #   나의 네 글자 — 결 벡터를 열여섯 자리로 접는다 (한가운데·문턱·이름)
│  │  ├─ axis/engine.ts         #   공통 리플레이 엔진 — 걸음·좌표·명명·이웃·변주·실천 (여덟 축이 공유)
│  │  ├─ axis/journey.ts        #   여정의 순서와 잠금 — 순차 해금·바로 앞 축만 재걷기·프로필 누적
│  │  ├─ axis/statement.ts      #   나의 문장 — 축을 지날 때마다 절이 하나 붙는다
│  │  ├─ axis/axes/*.ts         #   여덟 축의 데이터 — 축을 늘리는 일은 화면이 아니라 여기서
│  │  ├─ shelf/                 #   결 서재 — 구절(passages)·노래(tracks) 데이터와 결 매칭
│  │  ├─ chronicle.ts           #   결 연표 — 판의 봉인·계절·움직인 갈래
│  │  └─ together.ts            #   겹쳐보기 — 겹친 갈래·갈린 갈래·건넬 질문 하나
│  ├─ design-system/            # 토큰(styles.css)·관용구(recipes.ts)·컴포넌트
│  │  ├─ layout/ primitives/    #   앱 골격(오로라·화면·플로팅 CTA) · 낱개(버튼·칩·팝업·글·제목 복사)
│  │  ├─ orb/ icons/ fonts/     #   오브와 말풍선 · 인라인 SVG 아이콘 · 손글씨 서체 문지기
│  │  ├─ code/                  #   네 글자 표식 — 채워진 자리와 아직 비어 있는 자리
│  │  └─ chain/                 #   여정의 공통 골격 — 여덟 축이 함께 쓰는 화면·걸음 점·선택지·축 막대·상태 훅
│  └─ feature-axis/             # 축 피처 — 걷는 화면(AxisFlow)과 결과 카드(OutcomeCard) 하나로 여덟 축을 다 그린다
└─ docs/identity-os-design.md   # 제품 설계 (8축 프레임워크·네 글자·서재·연표·AI 코치·로드맵)
```

MFE 경계 규칙: 피처는 라우팅·저장 방식을 모르고 전부 앱 셸이 props로 주입한다. `identity-core`는 React조차 모르는 순수 TS — 테스트가 집중되는 곳.

**축이 다른 것은 데이터뿐이다.** 여덟 축이 같은 엔진(`axis/engine.ts`)과 같은 화면(`feature-axis` + `design-system/chain/`)을 쓰고, 축마다 정하는 것은 트리 데이터와 결과 해석(`AxisDef`)뿐이다. 그래서 축을 늘리거나 콘텐츠를 확장하는 일이 화면 작업이 아니라 데이터 작업이 된다. 축 데이터에는 함수(실천 카드 빌더)가 들어 있어 서버 컴포넌트 경계를 넘지 못하므로, 라우트 파일은 **축 id만** 넘기고 데이터는 클라이언트 경계 안에서 찾는다.

## 지켜야 할 것

- 깊은 물음은 축마다 셋까지 — 심문이 되지 않게. 그리고 모든 깊은 물음에 넘어가기.
- 성장 압박 속에 어떤 기능이 들어와도, **1→8의 순서와 "바로 앞 축만 다시 걷기"** 는 불변식이다. 뒤 축은 앞 축 위에 얹혀 있으므로. 계절이 열어주는 것도 중간 축 재걷기가 아니라 **한 판을 새로 걷기**다.
- 네 글자는 가장 잘 퍼지는 조각이라 **가장 큰 위험**이기도 하다. "네 글자만 보고 가는 서비스"가 되면 자기 이해는 사라지고 유형 테스트만 남는다 → 지름길 없음(여덟 축을 걸어야 봉인), 별도 결과 페이지 없음(언제나 가이드북 안), **궁합·점수·순위 없음**.
- 축 데이터를 손보면 `CENTER`가 어긋난다 — `code.test.ts`의 분포 테스트가 깨지면 다시 재는 것이지, 문턱을 헐겁게 하는 게 아니다.
- 서재에 줄을 더할 때는 인용을 짧게, 출처를 확인하고, 가사·본문은 싣지 않는다. 링크도 두지 않는다 — 제목만 복사한다.
